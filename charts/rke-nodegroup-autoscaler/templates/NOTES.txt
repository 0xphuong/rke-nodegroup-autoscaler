WARNING: cluster-autoscaler {{ .Values.clusterAutoscaler.image.tag }} does not match Kubernetes {{ $kube }}.
  cluster-autoscaler simulates scheduling with the scheduler code of its own version; with another minor it can
  misjudge where pods fit. Set clusterAutoscaler.image.tag to the latest v{{ $kube }}.x release
  (https://github.com/kubernetes/autoscaler/releases?q=cluster-autoscaler-{{ $kube }}).

rke-nodegroup-autoscaler is installed in {{ .Release.Namespace }}.

Node groups:
{{- range .Values.nodeGroups }}
  - {{ .name }}: {{ .minSize }}..{{ .maxSize }} nodes
{{- end }}

Check it:
  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "ngas.provider" . }}
  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "ngas.autoscaler" . }}
  kubectl -n {{ .Release.Namespace }} get configmap cluster-autoscaler-status -o yaml
  kubectl -n {{ .Release.Namespace }} get configmap {{ include "ngas.provider" . }}-state -o jsonpath='{.data.instances\.json}'
  kubectl get nodes -l {{ include "ngas.groupLabel" . }}

New VMs fetch their join script from https://<node IP>:{{ .Values.bootstrap.nodePort }}; the VM security group
must allow that, and the bootstrap log on a VM is /var/log/rke-nodegroup-bootstrap.log.

{{- if include "ngas.workerTemplateFromControlPlane" . }}
The worker template is read from the control plane node the provider runs on. After every `rke up` that changes
the cluster (Kubernetes version, kubelet args, control plane hosts) restart the provider to read it again:
  kubectl -n {{ .Release.Namespace }} rollout restart deploy/{{ include "ngas.provider" . }}
{{- else }}
After every `rke up` that changes the cluster (Kubernetes version, kubelet args, control plane hosts) re-take
the worker template and `helm upgrade --set-file workerTemplate.json=...`.
{{- end }}
RKE does not know about node group nodes and will not upgrade them: replace the existing ones.
